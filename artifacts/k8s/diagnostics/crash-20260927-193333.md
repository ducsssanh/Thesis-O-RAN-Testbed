# Host crash diagnosis — 2026-09-27 19:33:33 +07

## Conclusion

The host became unresponsive under combined CPU, thermal, memory, and container
reconciliation pressure. Plugging or unplugging USB-C/AC is the likely immediate
trigger: it forces a power/platform-profile and device-state transition while the
machine has almost no scheduling or thermal headroom. The patched SMF build was
an additional all-core load, while the host Kubernetes cluster was already
reconciling a large failed ONAP/O-RAN workload.

The user hard-reset the machine after the display froze. Therefore, the abrupt
journal ending does not prove that firmware performed a thermal shutdown. The
available evidence supports overload plus a power transition, but cannot isolate
the final fault to ACPI/UCSI, the graphics stack, or scheduler starvation because
the frozen system did not flush such an error to disk.

## Evidence

- Previous boot ended at 19:33:33 when the user hard-reset the frozen machine.
- From 19:33:01 through 19:33:05 the kernel repeatedly reported
  `Package temperature is above threshold, cpu clock is throttled` across several
  CPUs. The journal stopped about 28 seconds later.
- The ACPI thermal zone exposes `hot=102900` and `critical=103000` millidegrees C.
- Immediately after reboot, with no Docker build running, sensors still reported
  CPU/package temperatures of 100–101 C and both fans around 4500 RPM.
- The first freeze recorded `No ptyHost heartbeat after 6 seconds` followed by
  `systemd-journald: Under memory pressure, flushing caches`. The second recorded
  `gnome-shell: libinput ... your system is too slow` seconds before the reset.
- The host load average reached 23.23 on an 18-logical-CPU machine. The old host
  cluster had 1,827 Pod records, including hundreds in unknown/error states, and
  several Java processes each using more than one CPU.
- `thermald` is enabled but exits immediately with `Thermald can't run on this
  platform` and `Unsupported cpu model or platform`.
- No kernel OOM kill, kernel panic, machine check, UCSI failure, contemporaneous
  i915 GPU hang/reset, hardware error, or disk-space exhaustion was recorded.
  About 77 GiB remained free after reboot.
- The SMF log ends during compilation at 4%; no image was produced.

## Secondary host issue

The old cluster also exhausted inotify instances. containerd repeatedly logged
`failed to watch oom events ... too many open files`. This explains monitoring
and reconciliation failures but is not, by itself, evidence of the abrupt reset.

## Safe continuation condition

Do not resume an unrestricted parallel SMF build while the host is already near
100 C. First reduce the background cluster load or cap build parallelism, and
monitor the ACPI thermal zone with an abort threshold below its 103 C critical
trip point.

## Controlled retry at 19:45

A retry kept the upstream `--jobs` build behavior and used the host power-saver
profile. Temperature remained at 75–79 C, but available memory fell from about
2.2 GiB to 1.34 GiB by 9% compilation. A memory watchdog interrupted Docker with
SIGINT before the desktop became unresponsive. The host has no swap. Creating an
8 GiB temporary swap file was attempted but not performed because non-interactive
sudo authorization was unavailable.
